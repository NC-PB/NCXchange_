# Example tests

The examples of the specification as acceptance tests: `ExampleFormatTests` formats every `.ncx` example of `docs/spec/examples` and expects it back byte for byte (phase 0, P0-06). `ExampleCheckTests` checks every example STATIC without a machine file through the parser and the virtual machine: no ERROR (D103), and the diagnostics equal to `../Expected/<name>.check.txt` (phase 1, P1-04). `ExampleEventTests` records the events of `2.5D_FRAESEN.ncx`, run STATIC as `ncx check` runs it, and compares them with `../Expected/2.5D_FRAESEN.events.txt` (phase 1, P1-05). `ExampleMachineCheckTests` checks them with their machine files found by name in `machines/`: no ERROR, and the diagnostics equal to `../Expected/<name>.<machine>.check.txt` (phase 2, P2-04; D103, D104). `FanucReaderTests` and `HeidenhainReaderTests` read the example sources through the library, and `ConvertExampleTests` runs `ncx convert` on them with their machines by name: 2.5D_FRAESEN from both sources into the blocks of the example, `BOHREN.fanuc.nc` into `../Expected/BOHREN.ncx`, every source into what its reader reads (phase 3, P3-02, P3-05). `SiemensReaderTests` converts a hand-written 840D sl program with `siemens-840dsl-mill` by name, without an ERROR and with `RAW` only for `MSG`, `WORKPIECE` and `STOPRE`, and under `NCX_CORPUS` every `.mpf` of the corpus, the Hermle C22 U and the Burkhardt+Weber programs (phase 5, P5-01). The round trips through the readers and compilers (phase 3) join them here.
