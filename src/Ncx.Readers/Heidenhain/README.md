# Heidenhain

The reader of Heidenhain Klartext, iTNC 530 and TNC 640 (controllers `heidenhain.md` 1 to 7; the Heidenhain column of every section of `controller-mapping.md`): one file per concern, so that an NC programmer finds `TOOL CALL` in `HeidenhainToolCall.cs` and `CYCL DEF 200` in `HeidenhainCycles.cs`.

Start with `HeidenhainReader.cs`. It gives the structure pass the role of every block (`BEGIN PGM`, `END PGM`, `M30`, `M2`, the labels of `HeidenhainLabels.cs`, which decides in two passes which `LBL` is a subprogram and which a label), writes the complete header of D34 after `PROGRAM=BEGIN`, and reads every block by its first words, every block carrying its verb: `HeidenhainMotion.cs` (`L`, `LN`, `LP`, `FMAX`, `F`, `F AUTO`, `R0`/`RL`/`RR`, `M91`, the `IX` forms) with `HeidenhainArcs.cs` (`CC`, `C`, `CR`, `CT`, `CP`, `CP IPA` beyond 360 degrees as `ANGLE`) and `HeidenhainCorners.cs` (`CHF` and `RND` between two lines expanded into the `LINE` and `ARC` blocks they stand for, D58), `HeidenhainToolCall.cs` (`TOOL CALL`, `TOOL DEF`), `HeidenhainCycles.cs` (`CYCL DEF` of the machining cycles through the cycle catalog, `CYCL CALL`, `M99`, `PATTERN DEF` and `CYCL CALL PAT`, and `CYCLE=OFF` before the next non-cycle motion), `HeidenhainFrameCycles.cs` (cycles 247, 7, 8, 9, 10, 19 and 32, the chain of transforms in `HeidenhainChain.cs`), `HeidenhainPlane.cs` (`PLANE SPATIAL`, `PLANE AXIAL`, `PLANE RESET`), `HeidenhainFlow.cs` (`LBL`, `CALL LBL`, `CALL LBL REP`, `CALL PGM`, `FN 9` to `FN 12`), `HeidenhainQ.cs` with `HeidenhainExpression.cs` (`Q`, `QL`, `QR` names kept, `FN 0` to `FN 5`, formulas) and `HeidenhainFunctions.cs` (the M functions: the machine's tables, `STOP`, `M126`/`M127`, `M116`/`M117`, `M128`/`M129`, `M136`/`M137`, `M140`, `MFUNC`). `BLK FORM`, `APPR`/`DEP`, `TCH PROBE`, `FN 16`/`18`/`19`, the other `PLANE` forms and OEM cycles stay `RAW` with a WARNING; every word a concern reads is marked in `HeidenhainBlock`, and a word no concern reads keeps its block `RAW`, so nothing is dropped (D5).

`HeidenhainTokenizer.cs` cuts the file into blocks (the block number, `~` continuations, `;` comments, `* -` sections, `/`, the comma), `HeidenhainState.cs` holds what the reader knows of the file (the plane, the pole, the cycle definition, the chain, TCPM), and `HeidenhainCalls.cs` with `HeidenhainCallerState.cs` and `HeidenhainChanges.cs` the state a subprogram runs with and the state it leaves its caller (virtual machine 3.9). The codes are `RDR300` to `RDR499` in `../DiagnosticCodes.Heidenhain.cs`.

Never here: `ncx convert` (`Ncx.Cli`), the meaning of the program beyond what the source leaves implicit (the virtual machine), code for one machine (its TOML file and the cycle catalog `cycles/heidenhain.toml`).
