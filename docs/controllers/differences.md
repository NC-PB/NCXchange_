# How the three families differ

The same things a CAM postprocessor has to write, side by side. Every row is a place where a reader has to resolve something the source left implicit or a compiler has to write something the target insists on; the NCX word that carries the meaning is in the last column, and `../spec/controller-mapping.md` has the full rule per word.

| Thing | Fanuc (and the ISO dialects) | Heidenhain Klartext | Siemens SINUMERIK | NCX |
|---|---|---|---|---|
| How a block moves | `G0`/`G1`/`G2`/`G3` at the start of the block, modal: a block with only `X10.` moves the way the last G said | the verb is the block: `L` (line), `C` (arc about `CC`), `CR` (arc by radius), `CT`, `LP`/`CP` polar, `LN` with vectors; rapid is `FMAX` at the end of an `L` block | `G0`..`G3` modal as on Fanuc, plus `CIP` (through a point), `CT`, `INVCW`; `G0` may be linear (`RTLION`) or per axis | an explicit verb on every motion block: `RAPID`, `LINE`, `ARC=CW`/`CCW`, `RETRACT`, `HOME`, `CYCLE_CALL` |
| Feed | `F` modal, per minute or per revolution by `G94`/`G95` (mills, lathe systems B and C) or `G98`/`G99` (lathe system A) | `F` modal at the end of the block, `FMAX` for rapid, `F AUTO`; per revolution with `M136`, back with `M137` | `F` modal (also `F=2*R1`), `G94`/`G95`, `G93` inverse time, `FZ` per tooth, `FB` blockwise | `F` modal, `FEED_MODE=PER_MIN`/`PER_REV` |
| Arcs | end point plus `I J K` (center incremental from the start point) or `R` (signed for the long arc); plane by `G17`/`G18`/`G19`; helix by adding the third axis | `CC X Y` in its own block (absolute center) then `C X Y DR+`/`DR-`; or `CR X Y R5 DR-` with the radius; `DR-` is clockwise; polar arcs `CP IPA+737 DR+` sweep more than a turn | `I J K` incremental, or `I=AC(50)` absolute; `CR=` radius; `AR=` opening angle; `TURN=2` extra full turns on a helix; `CIP` with `I1= J1= K1=` | `ARC=CW X= Y= CENTER:X= CENTER:Y=`, `CENTER:IX=`, `R=`, `ANGLE=` for sweeps; helix by a tool-axis word |
| Tool call | `T1` prepares (mills) or changes (lathes, `T0101` = station and offset); `M6` changes; `T1 M6` in one block changes to 1; offsets by `G43 H1` and `D1` afterwards | `TOOL CALL 1 Z S1592 F500 DL+0.1`: number, tool axis, speed, feed and the offsets all at once; `TOOL DEF 2` prepares the next tool | `T1` or `T="DRILL_D8"` selects (changes directly on turrets), `M6` changes on mills, `D1` selects the cutting edge and with it length and radius; `T0` unloads | `PRELOAD=`, `TOOL=`, bare `TOOL`, `OFFSET:LEN=`, `OFFSET:RAD=`, combined `OFFSET=`, `RPM=` as separate words |
| Radius compensation | `G41`/`G42`/`G40` with the `D` register, in a motion block | `RL`/`RR`/`R0` at the end of the `L` block | `G41`/`G42`/`G40`, approach and retreat behaviour by `NORM`/`KONT`, corner behaviour by `G450`/`G451` | `COMP=LEFT`/`RIGHT`/`OFF` in the motion block |
| Datum | `G54`..`G59`, `G54.1 P1`.. for more; `G52` local shift replaces the previous `G52`; `G10 L2` writes the table | `CYCL DEF 247 Q339=1` selects a preset; `CYCL DEF 7.0`/`7.1 X`/`7.2 Y`/`7.3 Z` shifts, replacing the previous cycle 7 | `G54`..`G57` then `G505`..`G599`, `G500` off; `TRANS`/`ATRANS` programmable shift (`TRANS` deletes every earlier programmable frame, `ATRANS` adds), `G58`/`G59` per axis, `$P_UIFR[1,X,TR]=` writes the table | `ORIGIN=1`, `SHIFT X= Y= Z=` appended to a chain in program order, `SHIFT=RESET` |
| Rotation, mirror, tilt | `G68 R30`/`G69`, `G51.1`/`G50.1`, `G68.2` (tilted plane, spatial angles) with `G53.1` to position the axes, `G68.1` by axis angles | `CYCL DEF 10 ROT`, `CYCL DEF 8 MIRROR`, `PLANE SPATIAL SPA SPB SPC TURN/MOVE/STAY`, `PLANE AXIAL A B C`, `PLANE RESET`, older `CYCL DEF 19` | `ROT`/`AROT` (also `RPL=` about the plane normal), `MIRROR`/`AMIRROR`, `SCALE`, `CYCLE800(...)` with a mode word for axis-wise, spatial, projection or rotary-axes-direct angles and a direction word for positioning | `ROTATE=`, `MIRROR=`, `TILT A= B= C=`, `TILT_AXIS A= B= C=`, `MOVE=TURN/MOVE/STAY`, `ROT=TABLE/COORD` |
| Drilling cycles | one modal block `G81 G99 Z-21.7 R5. F565` defines and calls at its own position; following position blocks call again; `G80` cancels; `G98`/`G99` choose the return plane; `K` repeats; lathes drill along Z (`G83`) or X (`G87`) | `CYCL DEF 200 BOHREN` with `Q` parameters over several lines (`Q200` safety, `Q201` depth, `Q203` surface, `Q204` second clearance, `Q206` feed, `Q211` dwell), then `CYCL CALL` or `M99` in the positioning block | `CYCLE81(RTP, RFP, SDIS, DP, DPR, DTB, ...)` called once at the current position, or `MCALL CYCLE81(...)` then every position block calls it until `MCALL` alone; depths absolute or incremental by the trailing mode parameters | `CYCLE=DRILL SURFACE= CLEARANCE= DEPTH= SAFE= CYCLE_F= CYCLE_DWELL= CYCLE_RETRACT=` then `CYCLE_CALL X= Y=`, `CYCLE=OFF`; `AXIS=X` on lathes |
| Program frame | `%`, `O0001 (NAME)`, blocks, `M30` or `M2`, `%`; several `O` programs may follow each other in one file; subprograms `O0100` ... `M99` | `0 BEGIN PGM NAME MM`, consecutively numbered blocks, `END PGM NAME MM`; one program per file; subprograms `LBL 1` ... `LBL 0` after `M30` inside the program | `%_N_NAME_MPF` (or `_SPF` for subprograms), `;$PATH=...` comment, blocks, `M30` (`M2`, `M17`); a job archive holds several units in one file; `PROC NAME` ... `RET` for a subprogram with parameters | `FILE=BEGIN NCX=1`, `PROGRAM=BEGIN NAME= NUMBER=` ... `PROGRAM=END`, `SUB=BEGIN NAME=` ... `SUB=END`, `FILE=END` |
| Comments and structure | `( TEXT )` anywhere in the block; nothing else | `; TEXT` at the end of a block, `* - TEXT` as a structuring block that the editor shows in the outline | `; TEXT` at the end of a block or alone; `MSG("TEXT")` is a run-time message, not a comment; `GROUP_BEGIN`/`GROUP_END` structure the program in the editor | `COMMENT="..."`, `SECTION="..."` |
| Machine datum | `G53` in the block (also with variables, `G53 X#528`); `G28 U0 W0` / `G91 G28 Z0` reference point return | `M91` in the block (machine datum), `M92` (a second datum) | `G53` (one block), `G153`, `SUPA`; `G74` reference point; `G75 ... FP=` fixed points | `FRAME=MACHINE` in the block, `HOME X Z POINT=` |
| Numbers | dot as decimal separator; `X70.` with a trailing dot and `I-.534` with a leading dot are normal; a number without a point may mean the least input increment on old settings, so readers assume decimal-point programming | comma as decimal separator in the file (`X-6,964`), dot accepted by newer controls; the writer must use the comma; `~` continues a block over lines in cycle definitions | dot; `=` required after a multi-letter address (`X1=10`, `CR=5`, `S2=1000`); expressions allowed as values (`X=R1*2`) | dot; never rounded or reformatted by NCX, formatted by the compiler per `[format]` |
| Incremental | modal `G91` (systems B and C) or the addresses `U W H V` for X Z C Y in lathe system A; `G91` also inside `G28 Z0` | `IX IY IZ IA IB IC` prefix on the value (`L IX+30`), never modal | modal `G91` or `X=IC(30)` per word; rotary axes `DC()` shortest way, `ACP()`, `ACN()` | `IX=`, `IY=` ... per value, never modal |
| M functions | `M3`/`M4`/`M5`, `M8`/`M9`, `M0`/`M1`, `M30`/`M2`/`M98`/`M99` are common; everything else is the machine builder's (wait marks, chucks, C-axis modes, transfer) | `M3`/`M4`/`M5`, `M8`/`M9`, `M13`/`M14` (spindle plus coolant), `M0`/`M1`, `M30`; `M91`/`M92`, `M126`..`M129`, `M136`/`M137`, `M140`, `M118`, `M120`, `M138` are Heidenhain's own; the rest is the builder's | `M3`/`M4`/`M5` with a spindle number (`M2=3`), `M6`, `M17`, `M19`, `M70`, `M0`/`M1`, `M30`; the rest is the builder's | `SPINDLE=`, `COOLANT=`, `STOP=`, `ORIENT=`, `FUNC:name=state` from the machine configuration, `MFUNC=` as the fallback |
| Variables and flow | `#1`..`#33` local, `#100`.. common, `#500`.. permanent, `#1000`+ system; `[ ]` expressions; `IF [#1 GT 2] GOTO 10`, `WHILE [..] DO1` ... `END1`, `G65 P9010 A1 B2` macro call with letter arguments | `Q0`..`Q1999` (`QL` local, `QR` remanent, `QS` string); `Q1 = Q2 + 3` and `FN 0`..`FN 5`; `FN 9`..`FN 12 IF .. GOTO LBL`; `CALL LBL 1 REP 3`; `FN 18` system data; `FN 16` output | `R1`..`R99` (more by setting) and declared `DEF INT/REAL/STRING` names; `IF`/`ELSE`/`ENDIF`, `LOOP`, `FOR`, `WHILE`, `REPEAT`/`UNTIL`, `GOTOF`/`GOTOB`, `CASE`; `PROC` subprograms with typed parameters; `$AA_IW[X]` and the other system variables | `VAR:name=`, `{...}` expressions, `LABEL=`, `JUMP=` with `IF=`, `CALL=` with `ARG:`, `TIMES=`, `REPEAT=`, `$SYS_*` |
| Several channels | one program per path, `M100`..`M199` wait marks with `P` path lists, one file per path (Nakamura names the second path `.P-2`) | single channel (mill-turn with one program) | one program per channel, `WAITM(mark, 1, 2)`, `INIT`/`START`/`WAITE`, marks 0..99 | `CHANNEL=` in the header, `SYNC=` with `WITH=`, job manifest |
| 5-axis | `G43.4`/`G43.5` tool center point control, vectors by `I J K` with `G43.5`, `G68.2` planes, `G41.2` 5-axis radius compensation | `M128` and `FUNCTION TCPM`, `LN` blocks with surface normal `NX NY NZ` and tool vector `TX TY TZ`, `M126` shortest rotary path, `M116` rotary feed in mm/min, `M140 MB MAX` retract along the tool axis | `TRAORI`/`TRAFOOF`, orientation by rotary words, `A3= B3= C3=` direction vector, `A4=`..`C5=` surface normals, `LEAD`/`TILT`, `ORIAXES`/`ORIVECT`, `ORIWKS`/`ORIMKS`, `CYCLE832` for the tolerance | `TCPM=ON`, `TX TY TZ`, `NX NY NZ`, `ROTARY_PATH=`, `ROTARY_FEED=`, `RETRACT`, `TOLERANCE=` |
| Lathe specifics | X in diameters on almost every Fanuc lathe (parameter), `G96 S200` constant surface speed with `G50 S3000` (system A) or `G92 S3000` limit, `G97` rpm; the tool offset in the `T` word; `G50 X Z` (A) or `G92 X Z` (B, C) declare the current position | turning only on the TNC 640: `FUNCTION MODE TURN` makes X a diameter value, `FUNCTION TURNDATA SPIN VCONST:ON`, cycles 800..8xx | `DIAMON`/`DIAMOF`/`DIAM90` switchable in the program, `G96 S200 LIMS=3000`, `G97`, `SETMS(n)` selects the master spindle that `S`, `G95` and `G96` refer to, `PRESETON` declares a position | `DIAMETER=ON`, `CSS=ON`, `VC=`, `RPM_MAX=`, `SETPOS`, roles `MAIN`/`SUB`/`TOOL` |

Three consequences that shaped NCX, worth keeping in mind when a rule looks pedantic:

1. A Fanuc block says how it moves only when the mode changed; a Heidenhain block always says it. NCX takes the Heidenhain side (explicit verb) because a block that can be read alone is what a diff, a plugin and a human need. The readers resolve the Fanuc modality with their source-side virtual machine.
2. A Heidenhain tool call carries four things Fanuc writes in four places (number, axis, speed, offsets). NCX keeps them apart as words and lets the compiler assemble the target's form; the reader for Heidenhain splits, the reader for Fanuc keeps the offset words where the source had them (D7).
3. Fanuc cycles are single blocks that call themselves; Heidenhain cycles are definitions with a separate call; Siemens has both forms. NCX separates definition (`CYCLE=` with parameters, absolute coordinates along the drilling axis) and call (`CYCLE_CALL`), so all three read into the same words and the depth conventions (Fanuc absolute `Z`, Heidenhain relative to `Q203`, Siemens absolute or incremental by a mode flag) are converted once, in the readers.
